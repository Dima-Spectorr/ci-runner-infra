# One line per DISTINCT pair:
#
#     <cve-or-ghsa-id> <package> [free-text note]
#
# `#` starts a comment. The note is optional — this file records what the image
# CONTAINS, not a decision to tolerate it, and 273 seeded lines each carrying a
# sentence of invented prose would be 273 lines of nothing. Where somebody has
# actually looked at one, write down what they concluded.
#
# WHAT IT IS FOR
#
# `image-vuln-verdict.sh` blocks only on findings grype matched through a
# distro's own security feed, because for a version read out of a binary it
# compares upstream numbers and a backported fix is invisible to that
# comparison — a gate that blocked on those would be red on every image forever
# (the first real run: 273 such findings, none of them fixable here).
#
# The gap that leaves is a genuinely vulnerable module vendored into an
# image-installed binary. So what is enforced is the population's GROWTH: a pair
# in the scan and not in this file fails the build as VULN3. Adding it is a pull
# request, which is the review.
#
# By pair and not by count, deliberately. A count moves whenever the
# vulnerability database does; a new (id, package) pair is a new statement about
# this image.
#
# SEEDED FROM A REAL SCAN, AND NOW ENFORCING
#
# Seeded on 2026-08-26 from image build `1057f771` — the first build of this
# trigger to succeed end to end — which reported 21,279 findings, 0 blocking,
# and 273 fixable off-distro matches across the 117 distinct pairs below. The
# gate is therefore in ENFORCE mode: a pair in a later scan and not in this file
# is a red build (VULN3), and adding it is a pull request.
#
# What each group is, so a reader can judge a new line rather than pattern-match
# it in:
#
#   linux-kernel (105)  grype read the version out of the kernel binary and
#                       compared it against upstream. "Fixed in 6.19.9" against
#                       an Ubuntu ABI revision is not a statement about whether
#                       Ubuntu backported it — the `deb` entries for the SAME
#                       kernel produce thousands of matches and zero blocking,
#                       because there Ubuntu's own data is consulted.
#   golang.org/x/crypto (8)  vendored inside dockerd, containerd and snapd. This
#                       image cannot upgrade the module independently of the
#                       distro packages that ship the binaries.
#   stdlib (3)          the Go toolchain a vendored binary was built with.
#   google.golang.org/grpc (1)  same shape as x/crypto.
#
# A NEW pair in any of these groups still deserves a look: "vendored in a distro
# binary" is why it cannot block, not a reason it cannot matter. What has been
# ruled out here is the version comparison, not the vulnerability.
#
# Pruning a line that no longer appears is optional and never fails the build —
# the gate prints it as "no longer seen". Emptying the file is not pruning: it
# turns enforcement back off.
